# tl-parse v0.1 Component Assurance Contract

## Component Boundary

- The pinned tl-syntax revision implements the referenced graph, interval,
  span, proposition, and semantic-profile contracts.
- Input bytes are valid Rust UTF-8 strings; non-ASCII dialect characters are
  still rejected with UTF-8 byte spans.
- Callers select a semantic profile and finite logical limits deliberately.

## Required Behavior

- Successful parsing returns only an exact-profile, tl-syntax-validated graph.
- Any diagnostic or exhausted limit suppresses the document.
- Canonical output is deterministic, unambiguous, and bounded before emission.
- Repeated requests have byte-identical reports and canonical output.
- The public API owns no second temporal AST or evaluator.

## Failure Handling

Parser failures produce versioned diagnostics and report statistics. Formatter
failures return typed errors without partial output. CLI I/O and usage failures
remain distinct from invalid MLTL input.

## Controls

The matrix covers dialect mapping, graph validation, diagnostic goldens, each
resource bound, canonical/idempotent formatting, generated round trips,
malformed corpora, fuzz seeds, CLI behavior, and evidence/human boundaries.

## Replacement

A replacement must pass the same dialect, diagnostic, graph, canonical,
resource, corpus, CLI, and evidence tests. Automated evidence is candidate
support; source release and exceptions require the named human owner.
